AWS Data Exchange で日本のマーケティングに使えるデータ

日本のマーケティングで実際に効くのは、大きく 4 系統です。エリア単位のジオデモグラフィック(消費者セグメンテーション、所得、支出)、B2B の企業属性(ファーモグラフィック)、POS や求人や記事といった需要シグナル、そして人流・気象・地図といった外部要因。この 4 つを自社データの横に置く、という使い方になります。

先に制約を言っておくと、AWS Data Exchange (ADX) では個人を特定できるデータは原則として出品が禁止されています(合法的にすでに公開されている情報を除く)。つまり「日本の生活者の個人 ID に紐づくリスト」を買ってきて名寄せする、という発想は最初から成立しません。エリアか企業を軸にして、自社の顧客データへ属性を足す方向で設計してください。

まず ADX がマーケティングの文脈で何をしてくれるのか

ADX はサードパーティデータのマーケットプレイスです。ファイル、API、Amazon Redshift のデータシェア、Amazon S3 のデータアクセス、AWS Lake Formation という複数の配信形式に対応していて、サブスクライブすると自分の AWS アカウント側でそのまま扱えるようになります。

マーケティング用途で効いてくるのは、契約とデータ受け渡しの手間が消えることです。従来なら個別に NDA を巻いて、CSV を FTP で受け取って、更新のたびに手で置き換えて……となる部分が、サブスクリプションと S3 への export に置き換わります。日次更新のデータ製品であれば、プロバイダーが新しい revision を publish した時点で、こちらは同じジョブを回すだけで最新版が手に入ります。

公開情報によれば、ADX には 300 社以上のプロバイダーから 3,500 を超えるデータ製品が並んでいて、そのうち 1,000 以上は無料で使えるとされています。まず無料製品とサンプル製品で当たりをつけてから有料版に進む、というのが現実的な進め方です。

日本のマーケティングに効く 4 カテゴリ

① エリア単位のジオデモグラフィック

いちばん使いどころが分かりやすいのがこれです。日本全国の町丁目やグリッド単位で、世帯構成・年齢層・所得・支出傾向をまとめたデータ製品が出ています。

たとえば「Japan Consumer Segmentation」は、国勢調査・政府統計・商用データをもとに、日本の近隣エリアの社会経済的なプロファイルを分類したものです。国際比較用のセグメンテーションと、日本市場に最適化したセグメンテーションの 2 系統を持ち、日本市場向けのほうは 10 グループ 54 カテゴリに分かれているとされています。分析変数として、子どもの有無、成人の年齢、世帯人数、教育水準、住宅の広さ、地価・住宅種別、平均所得(現地通貨建て)などが含まれます。町丁目レベルのサンプル製品も公開されているので、粒度の確認はサンプルでできます。

グローバルに揃った粒度で欲しい場合は、Experian の「WorldView」系の製品があります。こちらは世界を 250m × 250m のグリッドで覆い、ジオデモグラフィック、可処分所得、消費支出、セグメンテーション、POI を提供するもので、日本単体の製品も別立てで出ています。国内だけでなくアジア数か国を同じ物差しで比較したいときは、こちらのほうが素直です。

使い方はシンプルで、自社の顧客マスタにある住所や郵便番号をエリアコードに寄せて、そこにセグメントを結合します。個人単位の属性は買えなくても、「うちの優良顧客はこのセグメントに偏っている」までは出せます。あとはその偏りをもとに、未開拓の同一セグメントのエリアへ配布や出店を寄せる、という流れです。

② B2B の企業属性(ファーモグラフィック)

B2B マーケティングなら、日本国内の法人データが対象になります。Techsalerator は日本国内 570 万社規模の企業データを ADX / AWS Marketplace に出していて、売上規模、所在地、従業員数、業種でセグメントを切れるとしています。用途としてはダイレクトマーケティング、ビジネスインテリジェンス、業界分析が挙げられています。

実務でよく効くのは、新規リスト作成よりもむしろ既存データのエンリッチメントです。自社の商談履歴に業種コードと従業員数レンジを後付けすると、「どのセグメントで勝っているのか」がようやく集計できるようになります。ここが埋まっていない会社は本当に多いです。

なお法人データは、日本の商習慣的な表記ゆれ(株式会社の前株・後株、旧社名、支店表記)で結合に苦労します。名寄せの精度が読めないうちに全社分を買うより、サンプルで自社リストとの突合率を測ってから判断してください。

③ 需要シグナル(POS・求人・記事)

ここに日本発のプロバイダーが並びます。2020 年 9 月に AWS Marketplace と ADX が日本法人のセラー・データプロバイダーに対応し、その時点で日本経済新聞社(記事データと POS データ)、QUICK(株式などのマーケットデータ)、JMDC(医療データベース)が製品を掲載しています。日経は記事データと POS データを日次で提供でき、意思決定や AI / 機械学習の分析に使える、という趣旨のコメントを出しています。

消費財のマーケティングであれば、POS データはカテゴリ内シェア、店頭価格、新商品の立ち上がりを見るための土台になります。記事データは、競合や業界のニュースを構造化して取り込み、話題量の変化を追う用途に向きます。

やや変化球ですが、求人データも日本市場のシグナルとして使えます。ADX には日本(JP)向けの求人票の履歴データ製品があり、企業がどの職種をどのタイミングで募集したかが分かります。SaaS や採用関連サービスのように「投資が動いている企業」を狙いたい場合、求人の増減は決算より早く出るシグナルです。

④ 外部要因(人流・気象・地図)

ADX には、モバイルアプリや SDK 由来のモビリティデータや、POI 単位の日次来訪者数といった製品が並んでいます。ただし、この手の製品は日本のカバレッジがまちまちです。グローバル製品の説明文に日本が含まれていても、実際の国内サンプル数が実用に足るかは別問題なので、必ず日本分のサンプルで確認してください。日本国内の人流に関しては、ADX 経由ではなく国内事業者と直接契約するほうが粒度もサポートも良い、という結論になることも普通にあります。

気象データは、需要予測と広告出稿の調整に直結します。API 形式のデータセットはリアルタイム性のある用途、つまり気象・マーケットデータ・位置情報に向いている、というのが ADX 側の整理です。飲料やアイス、衣料のように気温で売れ行きが変わるカテゴリなら、まずここから触るのが投資対効果は高いはずです。

日本のマーケで買う前に見る 5 点

ADX の製品ページは英語で、しかもグローバル製品が大半です。日本で使えるかどうかは、次の 5 点で切り分けると外しません。

確認項目見るべきポイント
日本のカバレッジ「global」表記でも日本の実データが薄いことがある。無料のサンプル製品で行数と地域分布を確認する
粒度都道府県単位なのか、市区町村なのか、町丁目・グリッドなのか。エリアマーケティングでは市区町村では粗すぎることが多い
更新頻度年次のスナップショットか、日次の revision 更新か。需要シグナル用途なら日次でないと意味がない
DSA(Data Subscription Agreement)プロバイダーの利用規約。広告配信への利用可否、再配布の可否、社外への出力可否がここに書かれている
配信形式ファイル / API / Redshift / S3 / Lake Formation のどれか。既存の分析基盤に合わせて選ぶ

とくに DSA は読み飛ばさないでください。データ製品をサブスクライブする時点で、価格・期間・支払スケジュール・DSA・返金ポリシーを含むオファー条件に同意したことになります。「買ったデータを広告のターゲティングに使ってよいか」は製品ごとに違います。

個人データは買えない、という前提

ADX には、掲載できないデータカテゴリが定められています。個人を特定できる情報は、それが合法的にすでに一般公開されている場合を除いて、データ製品に含めることができません。HIPAA 対象の PHI を含む製品は、AWS Artifact で BAA を結んだ HIPAA アカウントでないと export できない、という制御も入っています。

この制約は日本のマーケティングにとってむしろ好都合に働きます。個人単位の外部データを買って自社 DB にマージする設計は、そもそも個人情報保護法の第三者提供や本人同意の論点を全部抱え込みます。ADX で買えるのがエリア単位・企業単位のデータに寄っているぶん、法務の確認は「利用規約の範囲内か」に集中できます。

どうしても他社の顧客データと突き合わせたい場合は、データを買うのではなく AWS Clean Rooms の側の話になります。Clean Rooms は、参加企業が互いの元データを開示せずに共同分析するための仕組みです。小売とメーカーの共同分析のように、相手が持っている購買データと自社の広告接触データを重ねたい、という要件はこちらで設計します。

探し方と受け取り方

探すときは AWS Data Exchange のコンソール、または AWS Marketplace の検索を使います。カテゴリで絞ってから、製品名やタイトルに国名が入っているものを拾うのが早いです。まず「Japan」「Japanese」で検索し、無料製品とサンプル製品を先に試します。

サブスクライブしたあとは、権利を持っているデータセットが自分のアカウントから見えるようになります。CLI であれば、次のように ENTITLED を指定して一覧します。

# サブスクライブ済み(権利のある)データセットを一覧する
aws dataexchange list-data-sets --origin ENTITLED

# 特定のリビジョンのアセットを S3 へ export するジョブを作る
aws dataexchange create-job \
  --type EXPORT_ASSETS_TO_S3 \
  --details file://export-job-details.json

あとは S3 に落ちたファイルを Amazon Athena で読むなり、AWS Glue で加工するなりです。Redshift のデータシェア形式であれば export すら不要で、プロバイダー側のデータをそのまま Redshift から参照できます。自社の顧客データが Redshift にあるなら、この形式の製品を選ぶと結合が一番短く済みます。

コストの考え方も押さえておきます。ADX 自体にサブスクライバー向けの独立したサービス料金はなく、支払うのはデータ製品の価格です。加えて、export 先の S3 のストレージ料金やクエリの料金は通常どおり自分のアカウントに乗ります。公開価格が合わない場合は、プロバイダーと個別条件を詰める private offer という枠組みがあり、価格・期間・支払スケジュール・DSA・返金ポリシーを公開オファーと変えられます。既にプロバイダーと直接契約がある場合は、それを ADX 上の配信に載せ替える BYOS (Bring Your Own Subscription) も使えます。

  • 個々のデータ製品(Japan Consumer Segmentation、Techsalerator の日本法人データ、日本向け求人履歴データなど)の現在の提供状況・価格・カバレッジ。データ製品は入れ替わりがあるため、掲載終了している可能性があります
  • 日経・QUICK・JMDC の各製品が現在も ADX に掲載されているか、および提供内容の詳細
  • ADX の製品数(3,500 超)とプロバイダー数(300 超)、無料製品数(1,000 超)の最新値
  • AWS Lake Formation 形式のデータセットが preview を脱しているかどうか

日本のマーケティング用途では、製品説明の「global coverage」を鵜呑みにせず、必ず無料サンプルで日本分の実データを確認する。ここだけは省略しないでください。
